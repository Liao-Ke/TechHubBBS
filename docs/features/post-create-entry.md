# 优化：为发帖功能添加独立入口

| 属性 | 值 |
|------|-----|
| 分支 | `feature/post-create-entry` |
| 日期 | 2026-06-21 |
| 类型 | 优化 |
| 影响范围 | 前端 AppHeader.vue |

## 问题

用户发帖只能通过"草稿箱 → 空状态 → 去写帖子"或"草稿箱 → 继续编辑"间接进入 `/posts/new`，缺少直接入口。

路由 `/posts/new` 及其对应的 `PostCreatePage.vue` 均已完整实现（表单、草稿自动保存、版块选择、可见范围），仅缺导航入口。

## 修改方案

在 `AppHeader.vue` 中新增两处入口，均仅在登录后可见：

| 位置 | 实现 |
|------|------|
| 桌面端导航栏 | 搜索框后添加 `el-button`（`type="primary"`、`icon=EditPen`），文字"发帖"，点击跳转 `/posts/new` |
| 移动端抽屉导航 | "首页"链接后添加"发帖"链接，点击跳转 `/posts/new` 并关闭抽屉 |

## 文件变更

| 操作 | 文件 |
|------|------|
| 修改 | `frontend/src/components/common/AppHeader.vue` — 新增图标导入、桌面端按钮、移动端链接及样式 |

## 验证方式

- `pnpm build` 构建通过
- 手动验证：未登录时"发帖"不显示 → 登录后桌面端和移动端均显示 → 点击跳转 `/posts/new` → 正常发帖

## 已知限制

无。`PostCreatePage.vue` 本身已处理草稿恢复、自动保存、提交流程，入口变更不影响既有逻辑。
